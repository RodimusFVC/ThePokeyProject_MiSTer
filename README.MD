<h1 align="center">The POKEY Project</h1>

<p align="center">
  A cycle-exact Atari POKEY (C012294) in SystemVerilog, proven clock by clock against MAME
</p>

---

## Overview

POKEY is Atari's sound and I/O chip: four audio channels, polynomial noise, timers,
paddle (pot) scanning and a random number generator. It is in the 8-bit computers
and in a long list of Atari arcade boards.

This project is a **from-scratch re-implementation** of POKEY, written to match
MAME's `pokey.cpp` (0.289) **exactly, on every POKEY clock** - not "sounds about
right", but the same internal state after every step. It is built for the MiSTer
Atari arcade cores and replaces the POKEY those cores have used until now.

The proof is a Verilator lockstep rig: the unmodified MAME source is compiled into
the testbench, both models are driven by the same bus events, and the complete
internal state of the two (counters, poly registers, filters, pots, IRQ, output)
is compared after every clock. Any difference stops the run and reports the clock,
the register and both values.

## Target Games

The games whose POKEY traffic was captured from MAME and replayed through the rig:

| Game | MAME set | POKEYs | Pot inputs |
|---|---|---|---|
| Centipede | `centiped` | 1 | none |
| Warlords | `warlords` | 1 | 4 paddles (POT0-3) |
| Millipede | `milliped` | 2 | DIP switches through ALLPOT (both chips) |
| Maze Invaders | `mazeinv` | 2 | DIP switches through ALLPOT (both chips) |
| Multipede | `multiped` | 2 | DIP switches through ALLPOT (both chips) |
| Crystal Castles | `ccastles` | 2 | IN1 through ALLPOT (second chip) |

Multi-chip boards need nothing special: MAME keeps all state per device, the
datasheet shows no chip-to-chip pins, and each chip is simply a separate instance.

## Scope

Implemented, cycle-exact:

- Four audio channels: 8-bit and linked 16-bit counters, 64 kHz / 15 kHz / base-clock
  selection (AUDCTL), volume-only mode
- Poly counters (4, 5, 9 and 17 bit) with MAME's exact sequences and init behaviour
  (RANDOM is frozen while SKCTL holds the chip in init)
- High-pass filters (channel 1 by 3, channel 2 by 4)
- STIMER, IRQEN / IRQST timer interrupts
- Pot scanning (POTGO, POT0-7, ALLPOT); the counter stops at 228
- SKCTL init and bit 4 (async mode, for its audio effect on channels 3/4)

Not implemented (no traced game uses them; checked against a histogram of every
register write in the captures):

- Keyboard scan (KBCODE reads `09`, as MAME with no keyboard callback)
- Serial I/O: SEROUT / SERIN shifting, two-tone and serial clock modes (SKCTL bits
  3, 5, 6), the SOD / OCLK pins

## Using It in a Core

### Drop-in (`pokey_glue`)

`pokey_glue` takes the same ports as the old POKEY module, so a swap is the module
name plus, for Warlords, one parameter. Add `rtl/pokey_cx.qip` to the core's
`files.qip`, then:

```systemverilog
pokey_glue #(.POT_CMP(8'h0F)) pokey1   // was: pokey pokey1   (POT0-3 from the board's comparator)
(
    ...                                  // ports unchanged
);
```

| Parameter | Meaning |
|---|---|
| `POT_CMP` | Pots measured by the board's external comparator on `pot_in` (Warlords: `8'h0F`; others `0`) |

### Native (`pokey_cx`)

```systemverilog
pokey_cx #(.POT_CB(8'h00), .ALLPOT_CB(1'b0), .POT_EXT(8'h00)) pokey (
    .clk, .reset_n, .ce, .addr, .din, .wr, .rd, .dout, .pot_val, .allpot_ext,
    .irq_n, .out_raw, .channel_0_out, .channel_1_out, .channel_2_out, .channel_3_out,
    .pot_count, .pot_in, .pot_count_step);
```

| Parameter | Meaning (per chip, from the MAME machine config) |
|---|---|
| `POT_CB` | Pots with a `pot_r` callback; value from `pot_val`, sampled at POTGO like MAME |
| `ALLPOT_CB` | Chip has an `allpot_r` callback: ALLPOT reads return `allpot_ext`, and a read stores it (MAME behaviour) |
| `POT_EXT` | Pots measured by an external comparator instead (exclusive with `POT_CB`) |

- `ce` is one POKEY clock (the board's POKEY clock: 1.512 MHz on the Centipede board).
- `wr` may arrive on any `clk` edge; it is applied before a step on the same edge,
  matching MAME's write-then-step order.
- `dout` is combinational from the current state.
- `reset_n` is synchronous and gives MAME's `device_start` + `device_reset` state.

### Known differences, glue vs MAME

None of these is reached by any traced game:

| Item | Glue | MAME |
|---|---|---|
| ALLPOT callback store | Board mux supplies the value; no store (the old ports have no read strobe) | A read of ALLPOT stores the callback value |
| Pot value 0 (comparator) | Latches at the first count | Taken from the ALLPOT bit at POTGO |
| Paddle moving during a scan | Comparator follows it live | Value sampled once at POTGO |

Use `pokey_cx` directly with `ALLPOT_CB=1` for full MAME exactness on the ALLPOT store.

## Verification

### Method

1. **Reference.** MAME 0.289 `pokey.cpp` / `pokey.h` compiled *unmodified* against a
   small shim (`ref/shim/`). The build checks the md5 of the source, so the oracle
   cannot drift from MAME.
2. **Captures.** MAME runs each game headless with a Lua script that records every
   POKEY read and write with its clock. Input devices are disabled so captures are
   deterministic (three identical runs, identical md5).
3. **Scheduling model.** `mame2ptr` places each access at the POKEY clock where MAME
   performs it (including the board's timer syncs), and scores MAME's recorded read
   values against the reference at that position. The model was fitted to the data
   and reproduces MAME's read values on every game.
4. **Lockstep.** `tb_pokey.cpp` drives the RTL and the reference with the same trace
   and compares the full state after every event and every clock.

### Results

| Run | Result |
|---|---|
| Game traces, 6 games x attract + play (normal and merged-write modes) | 24 / 24 pass |
| Game traces through `pokey_glue` with the old port protocol | 12 / 12 pass |
| Directed tests T01-T14 (registers, init, clocks, noise, linked, filters, STIMER, IRQ, pots, AUDCTL) | 26 / 26 pass |
| Random fuzz, 32 seeds x 100 M clocks x 2 chips, std + Warlords builds, normal + merged | 128 / 128 pass |
| Fuzz through `pokey_glue` | 64 / 64 pass |

### The rig can fail

A comparison that never fails proves nothing, so the rig is checked against
known-bad designs:

| Control | Result |
|---|---|
| Previous POKEY RTL (Mark Watson), audio output only | Diverges on all 7 traces that produce sound (the other 5 are silent in attract mode) |
| 23 single-bug mutants of `pokey_cx` (`tools/mutate.py`) | 23 caught, 0 survivors |
| A deliberately planted register error (`--plant`) | Caught at the planted clock |

## Building and Running the Rig

Requirements: Verilator 4.204, g++ (C++17), Python 3. MAME 0.289 and the game ROMs
only to make new captures.

```bash
make -C verilator md5        # check the MAME reference is pristine
make -C verilator lfsr       # poly counter self-test vs MAME's tables
make -C verilator rig glue   # lockstep builds: tb_std, tb_war, tb_mil, tb_glue_std, tb_glue_war

verilator/tb_std --trace traces/centiped_play60.ptr                 # one game trace
verilator/tb_war --trace traces/warlords_play60.ptr --merge         # Warlords (pot callbacks)
verilator/tb_std --fuzz 1 --clocks 10000000 --fuzz-chips 2          # random fuzz, two chips

tools/run_m12.sh 100000000 22   # full regression -> verilator/out/
```

> **Local paths.** A few scripts still point at the author's machine and need
> editing before use elsewhere: the MAME binary and ROM folder in
> `tools/mame/run_capture.sh`, and `OLD_DIR` in `verilator/Makefile` (the previous
> POKEY RTL used as a control by `make old`, which is not part of this project).
